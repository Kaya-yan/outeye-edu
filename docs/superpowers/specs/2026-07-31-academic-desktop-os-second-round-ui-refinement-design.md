# OutEye Edu Academic Desktop OS 第二轮 UI 精修设计

- 日期：2026-07-31
- 状态：已确认设计，待用户审阅
- 适用阶段：整站 UI 重构第二轮精修
- 关联项目：OutEye Edu 1.0 / Academic Desktop OS / HTML 教学课件工作台

---

## 1. 背景

OutEye Edu 已完成 Academic Desktop OS 的首轮整站 UI 落地，并已通过构建验证。当前版本已经实现：

- 全局 token 与外壳系统
- 登录 / 注册页重做
- 分析页首轮工作台接入
- 项目管理 / 资源库 / 知识库首轮档案系统接入
- 首页首轮品牌场景接入
- 课件列表 / 详情页首轮视觉接入
- 前端构建通过，14 个前端路由可构建

首轮的价值在于：已经把整站从旧版深蓝半成品风格统一到新的 Academic Desktop OS 世界观中。

但首轮的主要完成度仍然停留在“壳层统一”。第二轮的任务不是继续平均美化所有页面，而是把最关键的产品链路打磨成可演示、可记忆、可感知的一条高完成度产品体验。

---

## 2. 第二轮目标

第二轮的核心目标是：

> 把首轮“统一视觉壳层”的版本，升级为一条围绕“分析到课件展示”的高完成度主演示链，同时让分析页更专业、档案系统更真实。

本轮不是整站平均抛光，而是明确主次：

1. **主演示链深打**
2. **分析页内部专业化精修**
3. **档案系统补真实交互**

第二轮结束后，用户应该明显感受到：

- 产品真的成体系了
- 分析结果真的会进入课件生产
- HTML 教学课件真的像平台核心能力
- Academic Desktop OS 不只是首页概念，而是一路成立的系统体验

---

## 3. 优先级与范围策略

### 3.1 第一优先级：主演示链深打

本轮主角链路为：

- 首页 `/`
- 分析页 `/analysis`
- 课件列表 `/courseware`
- 课件详情 `/courseware/[id]`
- 课件编辑器 `/courseware/[id]/edit`
- 课件展示端 `/courseware/[id]/present`

要求：

- 从入口到展示端形成连续叙事
- 相邻页面之间具备明确的状态接力感
- 课件工作台成为整条链最清晰的产品亮点
- 展示端成为整条链路的收束高光

### 3.2 第二优先级：分析页专业化精修

分析页不重做主结构，重点升级结果表达质量与工作台可信度。

重点区域：

- 白盒分析结果区
- 图表系统
- 洞察卡 / 教学建议卡
- Stepper 与状态反馈
- 课件生成出口区

### 3.3 第三优先级：档案系统补真实交互

范围：

- 项目管理 `/projects`
- 资源库 `/resources`
- 知识库 `/knowledge`

目标：

- 让抽屉隐喻从“视觉像”变成“交互也像”
- 补最有感知的层级、筛选、展开、定位反馈
- 不在本轮扩展为深度信息管理系统

---

## 4. 第二轮明确不做

为保证视觉完成度和演示质量，本轮明确不做以下事项：

1. 后端新能力扩张
2. 大规模信息架构重写
3. 编辑器内核重构
4. 资源库 / 知识库做成完整复杂管理系统
5. 所有页面平均精修
6. 新增长链路功能点来替代现有主链路精修

第二轮本质上是产品体验精修，不是一次新的全站研发周期。

---

## 5. 页面级设计分工

### 5.1 首页 `/`

#### 角色

主演示链的品牌入口页。

#### 第二轮目标

- 强化“分析到课件展示”的主故事线
- 让 Hero、按钮、辅助信息、场景块更明确导向课件工作流
- 让桌面叙事服务产品逻辑，而不是只提供氛围

#### 精修方向

- 主 CTA 与次 CTA 层级更明确
- 与课件工作台相关的品牌块更像后续能力预告
- 功能说明不再平均分布，分析与课件相关模块明显前置
- 首页的品牌感保留，但要让用户快速理解“这套系统的主亮点是分析结果进入课件工作台”

#### 目标感受

用户看完首页后，应自然理解：平台最值得看的不是功能数量，而是分析到课件展示的完整链路。

---

### 5.2 分析页 `/analysis`

#### 角色

主演示链的核心工作台中段。

#### 第二轮目标

- 从“可用流程页”升级为“成熟专业分析台”
- 强化 Step 2 / Step 3 / Step 4 的结果表达质量
- 强化“生成教学课件”作为自然出口，而不是附属按钮

#### 精修方向

- 保持输入区基本结构不变
- 精修白盒结果区的信息等级
- 精修双源检索结果区的摘要质量与结构层级
- 精修教学方案区的完成感与结果收束感
- 把“生成教学课件”升级为结果页中顺理成章的下一步

#### 目标感受

用户在分析页最强烈的感受应是：结果有依据，而且这些结果会自然流向后续课件生产。

---

### 5.3 课件列表 `/courseware`

#### 角色

主演示链中的生产入口与课件资产总览页。

#### 第二轮目标

- 从“有课件列表”升级为“真的是课件工作台首页”
- 强化起点、项目状态、最近编辑、组件库入口的组织感
- 形成子产品首页完成度

#### 精修方向

- 强化三种起点：从教案生成 / 空白新建 / 导入 HTML
- 列表卡片更像工作中的课件资产，而非普通内容列表
- 组件库入口更像系统入口，而不是普通次级按钮
- 页面结构更明确体现“创建、继续、管理、沉淀”四种动作

#### 目标感受

用户进入后应感受到：这不是导出页，而是一个真正管理课件项目的地方。

---

### 5.4 课件详情 `/courseware/[id]`

#### 角色

主演示链中的课件项目控制台。

#### 第二轮目标

- 强化项目、版本、展示配置的关系
- 让版本历史、展示配置、项目信息更有控制台感
- 让“进入编辑器 / 课堂展示 / 提取组件”更像项目操作，而不是散动作

#### 精修方向

- 版本历史更像版本栈
- 展示配置与项目信息更像项目控制面板
- “提取为组件”动作自然地嵌入项目语义中
- 页面结构兼具档案页秩序和控制面板感

#### 目标感受

用户应感受到：课件不是一次性文件，而是一个可迭代、可提取、可展示的项目对象。

---

### 5.5 编辑器 `/courseware/[id]/edit`

#### 角色

主演示链中的生产力主舞台。

#### 第二轮目标

- 不能停留在“外壳接入新版”
- 要把编辑器整体拉进 Academic Desktop OS 体系
- 优先建立平台化工作台感，而不是简单换皮

#### 精修方向

- 顶部工具区、保存状态、模式标识、返回路径、展示入口整体重设计
- 编辑器外围布局、背景、控制区、提示层统一到 Workbench Scene
- 如果允许改动 iframe 内部，则优先统一：
  - 画布外背景
  - 面板层级
  - 常用按钮 / 标签 / 轻提示
  - 空态 / 选中态 / 占位态
- 保证用户不会产生“跳到外来编辑器”的割裂感

#### 目标感受

用户应感受到：自己不是跳到一个外部工具，而是在同一系统中进入了更深层的生产工作区。

---

### 5.6 展示端 `/courseware/[id]/present`

#### 角色

主演示链的终点与高光页。

#### 第二轮目标

- 明确区分编辑态与展示态
- 让展示端具备真实课堂控制台气质
- 让 slides 和 longform 两种模式都有成立的课堂使用感

#### 精修方向

- 工具条、计时器、备注、导航、黑屏等控制功能更克制专业
- slides 模式更像演示控制台
- longform 模式更像课堂阅读与讲解界面
- 控件在需要时让位于课件内容，不抢内容主位
- 进入展示态和返回编辑态都保持同一体系感

#### 目标感受

用户应感受到：HTML 课件不是网页预览，而是真的可以拿来上课。

---

### 5.7 档案系统页：`/projects` `/resources` `/knowledge`

#### 角色

主演示链背后的支撑秩序层。

#### 第二轮目标

- 让抽屉隐喻从装饰性语言变成可信交互
- 保证三页同属 Archive Scene 家族
- 但不在本轮扩展为深度复杂系统

#### 精修方向

- 抽屉展开 / 收起具备明显层级变化
- 当前激活抽屉状态清晰
- 筛选、分类、字母索引、定位反馈始终可感知
- 资源库与知识库保持同结构、不同语义
- 项目管理页维持档案秩序但不抢主演示链焦点

#### 目标感受

用户应感受到：档案系统不是装饰，而是整个平台背后的信息秩序基础。

## 6. 具体精修项

### 6.1 主演示链：从页面连续升级到状态连续

第二轮主演示链要解决的核心问题，不是单页不够好，而是页面之间的接力感还不够强。

#### 首页 → 分析页

精修重点：

- 强化首页 CTA 主次
- 用更明确的文案和品牌块承接分析工作流
- 让品牌入口不再平均介绍所有模块，而是明显偏向主链路

#### 分析页 → 课件生成

精修重点：

- 让 Step 4 教学方案区更有结果完成感
- 让“生成教学课件”成为自然下一步，而不是附属动作
- 提升从方案到课件的语义说明与生成成功反馈

#### 课件列表 → 详情 → 编辑器

精修重点：

- 让列表卡片像课件资产卡
- 让详情页像项目控制台
- 让“进入编辑器”更像继续工作，而不是跳页

#### 编辑器 → 展示端

精修重点：

- 让进入展示端的动作具备明确节奏与仪式感
- 让展示端像课堂使用终态，而不是网页预览态
- 返回编辑态后也保持系统内连续性

---

### 6.2 分析页：从步骤流程升级到专业工作台

#### 白盒分析结果区

目标：建立清晰的信息等级。

建议：

- 先给最重要结论，再给细项
- CEFR、可读性、难点、教学洞察分层明确
- 高价值结论卡前置，原始统计卡后退

#### 图表系统

目标：让图表成为证据，而不是装饰。

建议：

- 颜色完全收口到 Morandi / Academic token
- 图表标题、说明、注释、空态统一语言
- 图表旁必须有简短解释

#### 洞察卡 / 教学建议卡

目标：从“内容很多”升级为“结构可读”。

建议：

- 统一为“指标 / 含义 / 教学影响 / 建议动作”结构
- 减少松散段落，强化结构化阅读
- 高置信结论与一般提示分开层级

#### Stepper 与状态反馈

目标：让流程像专业工具。

建议：

- 当前步骤、完成步骤、等待步骤层次更清晰
- loading、成功、失败反馈更成熟
- 让“已完成方案，可进入课件生产”状态更明显

---

### 6.3 课件工作台：从接上了升级到像核心子产品

#### 课件列表页

精修重点：

- 三种创建方式层级更清楚
- 最近项目、模式、来源、状态更有秩序
- 组件库入口更像系统模块入口

#### 课件详情页

精修重点：

- 版本历史像版本栈
- 展示配置与项目信息像控制面板
- “提取为组件”动作更合理地嵌入工作流

#### 编辑器页

精修重点：

- 顶部控制区重设计
- 工作台外围背景与层级统一到 Workbench Scene
- 若可改 iframe 内部，优先统一面板标题、操作按钮、空态、选中态、画布边界

#### 展示端

精修重点：

- slides 模式像演示控制台
- longform 模式像课堂阅读与讲解界面
- 工具条、导航、计时、备注、黑屏状态更克制专业

---

### 6.4 档案系统：从像抽屉升级到会工作

#### 抽屉展开 / 收起

- 展开后有明确层级变化
- 当前抽屉激活状态清晰
- 收起过程带有归档感

#### 定位与筛选反馈

- 分类 / 字母 / 标签切换后有明确定位反馈
- 当前筛选状态始终可见
- 列表与抽屉关系清楚

#### 条目层级

- 标题、摘要、标签、状态、来源更有主次
- 资源库与知识库结构相似，但语义明显不同

## 7. 设计取舍

### 本轮做深

- 课件工作台主演示链
- 分析页结果表达
- 展示端控制感

### 本轮做到位但不过深

- 资源库 / 知识库 / 项目页抽屉交互
- 首页品牌氛围加强

### 本轮暂不展开

- 新增大功能
- 编辑器内核重构
- 档案系统深度信息架构扩张
- 全站平均精修

## 8. 验收标准

### 8.1 主演示链验收

从首页到展示端走一遍时，应满足：

- 每一步都能自然进入下一步
- 用户不会感觉像在不同系统间跳转
- 课件工作台是整条链最明确的核心亮点
- 展示端是演示时的收束高光

成功标志：

- 首页清楚引向主演示链
- 分析页生成课件动作自然且重要
- 课件列表 / 详情 / 编辑 / 展示四页具备一致子产品感
- 演示时这条链路可以连续讲完，而不需要额外解释页面关系

### 8.2 分析页验收

成功标志：

- 最重要结论一眼可见
- 图表和结果卡属于同一视觉系统
- 洞察卡 / 建议卡可快速扫读
- Stepper、loading、成功、失败反馈更成熟
- “生成教学课件”在 Step 4 中成为顺理成章的出口

### 8.3 课件工作台验收

成功标志：

- 列表页像工作台首页
- 详情页像项目控制台
- 编辑器页像平台内部深层生产区，而不是外来嵌入工具
- 展示端像课堂控制界面，而不是普通网页预览

### 8.4 档案系统验收

成功标志：

- 抽屉展开 / 收起有真实层级感
- 筛选、定位、当前状态反馈清晰
- 资源库与知识库同构但不同义
- 项目页、资源页、知识页在交互上更像同一个 Archive Scene 家族

### 8.5 视觉系统验收

成功标志：

- 首页更像品牌入口
- 分析页更像专业工作台
- 档案系统更像秩序容器
- 课件工作台更像生产力中心
- 展示端更像使用终态

统一的是世界观，不是所有页面长得一样。

### 8.6 范围控制验收

成功标志：

- 没把本轮做成全站重写
- 没把档案系统做成无限扩张
- 没把编辑器改造拖成大工程
- 精修集中在最影响感知的页面与交互上

### 8.7 技术验收

最低要求：

- `npm --prefix frontend run build` 继续通过
- 主演示链相关页面全部可构建
- 新增交互不破坏现有主链路
- 关键页面在视觉和状态上没有明显断裂

### 8.8 一句话验收

如果第二轮成功，最终应达到：

> OutEye Edu 看起来不再只是“已经有很多功能的原型”，而是“围绕分析到课件展示这条链路，已经形成了高完成度产品体验的系统”。

---

## 9. 实施建议

第二轮建议按以下顺序推进：

1. 主演示链中的分析页出口与课件列表 / 详情 / 编辑 / 展示端
2. 分析页内部结果卡、图表、洞察卡、状态反馈
3. 首页品牌叙事向主演示链收束
4. 项目 / 资源 / 知识页的抽屉交互补强

这样能够优先保证“最能拿去演示的链路”尽快达到高完成度，再把支撑页补到可信状态。
