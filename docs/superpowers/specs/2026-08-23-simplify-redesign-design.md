# OutEye Edu 1.0 界面简化重构 + HTML 工作台设计

- 日期：2026-08-23
- 状态：待用户审阅
- 范围：前端信息架构重构、视觉方向、术语与文案、HTML 工作台（一期集成 + V2 技术路线）、细节修复与排查

## 1. 背景与目标

大学英语老师群体（不擅长科技产品）实测后反馈 6 大问题：首页复杂不知道干什么、术语过于科技化、CEFR 等级看不懂、时长输入 bug、导出全失败、缺指引且信息冗余。

核心方向：参考 DeepL 的产品逻辑做减法——登录即工作页；资源库与知识库合并只留上传；项目管理改为历史记录并放导航最后。

设计原则：

1. 登录后第一个画面就是工作本身，不做营销首页
2. 所有文案使用老师能理解的中文，不用科技词汇
3. 每一步都有明确下一步，信息密度宁少勿多
4. 保留 Morandi 色系于标签与图表，主体视觉转向清晰工具风

## 4. 页面设计

### 4.1 工作台（`/`）

DeepL 式布局：

- 居中一行大字（首页文案如上）+ 两行小字
- 粘贴区：大输入卡片；左下"上传文件"，右下"开始分析"主按钮
- "教学设置（可选）"默认收起，点开展开：课时长度 / 课型 / 班级人数 / 学生水平（中文标签）/ 生成模式
- 分析开始后页面进入现有多步流程（分析结果 → 教案审阅 → 确认闸门 → 生成课件），流程内组件沿用现有实现，仅换文案与视觉

### 4.2 历史记录（`/history`）

- 标题"历史记录"+ 副标题"每条备课记录都保存在这里，点击可继续"+ 一个搜索框（按课文标题）
- 平铺列表，每行：课文标题 + 进度徽章 + 日期 + 进入箭头
- 进度徽章（流程位置）：分析中 → 分析完成 → 教案已确认 → 课件已生成
- 删除：状态侧栏、筛选抽屉、4 张计数卡全部移除

### 4.3 我的资料（`/materials`）

- 标题"我的资料"+ 副标题"上传教学大纲、词表或背景资料，分析课文时会自动参考"
- 一个拖拽/点击上传区（PDF/Word/TXT/MD）+ 文件列表（文件名 / 日期 / 删除）
- 删除：检索问答、热门问题、双 Tab、RAG 状态徽章

### 4.4 个人中心（`/profile`）

信息架构不变（账号/安全/偏好/我的内容/关于）。"关于"并入首页删除的营销内容精简版：一句话定位、3 条核心能力、理论依据压缩为一段引用、技术架构一句话。ICP 备案保留。

### 4.5 HTML 工作台导入页（`/html-workbench`）

- 标题"HTML 工作台"+ 副标题"上传 HTML 课件，像改 PPT 一样修改每一个细节"
- 上传文件 / 粘贴代码 / 加载示例三种导入方式 + "开始编辑"主按钮
- 强调演示优先心智："先看效果，再修改"——进入编辑器后用现有"预览"按钮先看整体效果再动手

## 5. 视觉设计方向（③ 清晰工具风）

结论：主体转向清晰工具风，Morandi 色降级到标签与图表。

设计 tokens（示意，实现时以 OKLCH 校准）：

| Token | 值 | 用途 |
|---|---|---|
| background | #ffffff / #f9fafb 分层 | 页面底 |
| foreground | #111827 | 正文 |
| primary | #2563eb | 主按钮、当前导航项、链接 |
| primary-hover | #1d4ed8 | 悬停 |
| muted | #f3f4f6 + #6b7280 | 次级按钮、说明文字 |
| border | #e5e7eb / #d1d5db | 卡片、输入框 |
| sage / gold / rose（Morandi） | 保留现值 | 仅用于进度徽章、图表、标签分类 |

规则：

1. 正文对比度 ≥ 4.5:1；大字（≥18px 或粗体 ≥14px）≥ 3:1；placeholder 同正文要求
2. 层级靠字号 + 字重对比（相邻层级 ≥1.25 比例），不靠颜色堆叠
3. 动效只保留三类：hover/聚焦反馈、流程完成反馈、面板展开收起；时长 180-280ms
4. 暗色主题做③的同名变体：深灰蓝底（不用纯黑）、主色提亮一档；沿用 `[data-theme="dark"]` 覆盖机制与防 FOUC 脚本
5. 编辑器内核（V1/V2 自带主题）不强制统一，导入页用产品风格衔接

## 6. HTML 工作台

### 6.1 一期集成（V1 内核先顶上）

- 现有 `public/editor/`（index.html + 20 个 vanilla JS 模块）原样保留，不改内核
- `/html-workbench` 为产品风格导入页（4.5 节）；"开始编辑"把内容经 sessionStorage 中转，跳 `/editor/index.html#import=<key>` 自动载入，无需手动粘贴
- 课件流程打通：教案确认 → 生成 HTML 课件 → 出现"去 HTML 工作台精修"按钮 → 同一中转协议
- 登录保护：Next.js middleware matcher 增加 `/editor/:path*` 与 `/html-workbench`，未登录跳登录页
- 编辑器内部保存/快照维持浏览器本地行为，不新增后端存储
- 中转协议设计为引擎无关（key → sessionStorage → URL hash），V2 就绪后底层整体替换、产品入口不动

### 6.2 V2 技术路线（正式方向，用户已确认投入）

核心范式：Run → See → Point → Patch。不要求网页适应编辑器，让编辑器适应网页：浏览器负责渲染，编辑器只理解浏览器最终呈现的视觉对象。

五大核心引擎（长期研发投入排序）：

1. Visual Object Engine——用户点到的视觉对象（非 DOM 元素）
2. Target Resolver——页面变化后仍能找到对象（selector + 结构/内容/几何指纹 + 模糊评分）
3. Patch Engine——非破坏性覆盖（原网页 + Patch 集 = 当前编辑结果），统一支撑 Undo/快照/Diff/导出/AI
4. Layout Intelligence——拖/拉/插入在 Flex/Grid/Flow/Absolute 下产生合理 CSS
5. Runtime State / Animation Engine——运行中网站冻结为可编辑视觉状态

关键架构决定：

- Host 与用户网页 Origin 隔离，postMessage RPC 通信；不可信网页不与主产品共享 Origin
- 所有编辑走 Command Engine 单一写入路径（AI 也只产 Command，经 Schema 校验，禁止直接操作 DOM）
- 渐进编辑能力分级：Deep Edit → Visual Edit → Object Edit，不出现"无法编辑"的二元结果
- Runtime Patch（让眼前正确）与 Source Patch（写回源码）分离，一期只做 Runtime Patch + 保真导出（追加 `<style id="ve-export-patches">`）

阶段划分与闸门：

| 阶段 | 内容 | 预估（1 人 + AI 结对，每日 4-6h） | 闸门 |
|---|---|---|---|
| Phase 0 技术验证 | Runtime Bridge、视觉拾取、浮动 Inspector、Patch + Undo、动画冻结、20-50 页 benchmark | 2-3 周 | 视觉编辑成功率未明显超过 V1 则停止/缩范围 |
| Phase 1 基础产品 | 拖/缩/旋、图片替换、inline 文本、Target Resolver、Mutation 恢复、保真导出 | 4-6 周 | 通过后替换 V1 内核 |
| Phase 2 网站能力 | 多页、Preview Server、SPA 路由、URL 导入（含 SSRF 防护） | 3-5 周 | 按产品需要 |
| Phase 3 复杂对象 | Pseudo/Shadow DOM/SVG/Flex-Grid 智能/动画系统 | 4-8 周 | 长尾 |
| Phase 4 AI | Point & Prompt（后端 LLM 设施现成） | 2-3 周 | 建立在稳定 Command/Patch 之上 |

- 针对本产品用例可走 V2-lite：用户编辑对象是平台生成的静态 HTML 课件（单文件、无框架、无路由），可砍掉 Phase 2 与大半 Phase 3，约 5-7 周到可替换内核
- Benchmark 第一批素材：平台生成的 HTML 课件 30-50 个（后续扩到 100+）
- 核心指标：Visual Edit Success Rate（Load/选择/Target 恢复/文本/样式/移动/缩放/导出保真分项统计）
- 红线（不做的）：不自研 Layout Engine、不把 DOM Node 当长期模型、不让 AI 直接操作 DOM、不无脑 `!important`、不关闭浏览器安全边界、不为冻结 JS 动画猴补丁所有 API
- 代码组织：`runtime-editor-v2` 独立目录/分支，不复用 V1 但可搬代码（iframe/selection/undo 等）

## 7. 细节修复与排查

| 项 | 方案 |
|---|---|
| 时长输入 bug | 允许清空不自动跳 9；失焦为空回退默认 90；步进按钮 ±5，范围 5-180，超界文字提示 |
| 导出失败排查（实测弹错误提示，前后端均在跑） | 现场复现：浏览器 Network 响应码 + 后端日志；重点查 rewrite 目标（NEXT_PUBLIC_API_URL）、token 过期 401、依赖缺失 |
| 图片上传失败排查（实测弹错误提示） | 现场复现：OCR 端点（aliyun 引擎凭证为头号嫌疑）、前端 accept 与大小限制 |
| 错误提示统一 | 失败 toast 带具体原因（网络连接失败 / 登录已过期请重新登录 / 文件格式不支持）；导出按钮 loading 防重复点击 |

## 8. 错误处理

- 所有 fetch 失败按状态码分三类提示：网络层（无法连接）、认证层（401/403 → 提示重新登录并跳登录页）、服务层（5xx → 提示稍后重试）
- 导出/上传等长操作统一 loading 态 + 完成反馈
- 历史记录为空、我的资料为空给引导空状态（"还没有记录，去工作台开始第一课"）

## 9. 测试与验收

1. `npm run build` 通过，无新增警告
2. 浏览器全流程手测：登录 → 粘贴课文 → 分析 → 审教案 → 确认 → 生成 HTML 课件 → HTML 工作台精修 → 三种格式导出
3. 历史记录进入续做；旧路由重定向生效
4. 暗色主题切换正常（含新页面）
5. 用 web-design-guidelines skill 对新页面跑 UI 审查，修掉高优先级问题
6. 导出与图片上传在现场环境复现并修复（验收即以用户实测通过为准）

## 10. 明确不做的事

- 不改 V1 编辑器内核样式与功能
- 不做导航"使用指引"常驻入口（指引融入工作台空状态与流程文案）
- 不做"语言切换""默认导出格式"偏好项（沿用既有决定）
- 本次不动后端 API 结构（除排查导出/OCR 所需的修复）
- V2 Phase 2-4 不在本次重构范围内，按 6.2 闸门另行启动
