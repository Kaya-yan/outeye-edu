# OutEye Edu 教学课件工作台（HTML 核心）设计文档

- 日期：2026-07-28
- 状态：已完成设计确认，待实现规划
- 适用阶段：中期升级
- 关联项目：OutEye Edu 1.0

---

## 1. 背景与目标

OutEye Edu 当前已具备：

- 课文白盒分析
- Wiki + RAG 双源检索
- 教学方案生成 / 修订
- PPT / DOCX / HTML 导出

团队在中期阶段决定新增“教学课件工作台”模块，并将 **HTML 提升为与 PPT 并列的一等教学产物**。团队判断 HTML 在未来教学中将越来越重要，部分场景下甚至可能替代 PPT；同时，高校教师已存在直接使用 HTML 进行课堂展示的实际趋势。

本次升级的目标不是删除 PPT / Word，而是：

1. 保留 PPT / Word 作为传统兼容交付路径
2. 将 HTML 从“导出格式”升级为“课件项目工作流核心能力”
3. 让老师像修改 PPT 一样高效修改 HTML 课件
4. 支持课堂直接使用 HTML 课件进行展示教学
5. 沉淀教学组件库，并逐步形成官方 + 个人 + 社区共享的组件生态

---

## 2. 设计结论摘要

本模块正式定位为：

> **教学课件工作台（以 HTML 为核心能力）**

它是 OutEye Edu 内部新的一级能力模块，不是单纯的 HTML 导出按钮，也不是独立的通用网页编辑器工具。

模块整体采用以下设计原则：

- **HTML 与 PPT 并列**，不替代 PPT / Word
- **双入口**：分析页进入 + 独立导航进入
- **双模式**：幻灯片式 / 长页面式共存
- **双层模型**：教学结构层 + 课件文档层
- **重编辑优先**：平台内支持强编辑能力
- **人工编辑优先**：AI 主要用于初次生成，后续以人工精修为主
- **课堂展示态独立存在**：编辑态与展示态彻底分离
- **组件库生态化**：官方、个人、社区三层组件库

---

## 3. 产品定位

### 3.1 模块定位

教学课件工作台承接教案生成结果，将其转化为：

- 可展示的 HTML 教学课件
- 可编辑的课件项目
- 可版本管理的教学资产
- 可导出的课堂交付物

平台未来形成两条并列产出路径：

### 传统交付路径

- 教学方案 → PPTX
- 教学方案 → DOCX

### 新型课堂路径

- 教学方案 → HTML 课件项目 → 可视化编辑 → 课堂展示 → HTML 导出

### 3.2 核心价值

本模块的核心价值不是“生成 HTML”，而是：

- 让 HTML 成为真正可使用的课堂课件形态
- 让老师不写代码也能高效编辑 HTML
- 让课件不只是文件，而是可保存、可复用、可分叉的项目
- 通过教学组件库与社区共享机制形成持续增长的内容生态

## 4. 第一阶段范围

虽然本次中期升级追求完整闭环，但第一阶段必须聚焦在以下主工作流：

> **生成 → 编辑 → 保存版本 → 展示 → 导出**

### 4.1 第一阶段必须完成的能力

1. 从教学方案生成 HTML 课件项目
2. 导入已有 HTML 创建课件项目
3. 从空白模板新建课件项目
4. 平台内可视化强编辑
5. 版本快照与恢复
6. 幻灯片式 / 长页面式课堂展示端
7. HTML 单文件与完整课件包导出
8. 官方组件库 + 个人组件库 + 社区共享组件的最小闭环
9. 保留现有 PPT / Word 导出能力

### 4.2 第一阶段明确不做的内容

以下内容明确排除在第一阶段之外：

1. 学生端实时互动（扫码答题、实时投票、云端联动）
2. 多人实时协同编辑
3. 深编辑后无损互转 slides / longform
4. 深编辑后的 HTML 高保真反导出 PPT / Word
5. 开放式插件生态
6. 大型公网公开发布平台

说明：

- 双模式“共存”在第一阶段指：可基于同一教学结构派生两种模式的课件项目或版本；不承诺任意深编辑后的一键无损互转。
- PPT / Word 继续作为传统交付格式保留，但不承担 HTML 深编辑后的反向承接职责。

## 5. 用户入口与总体流程

### 5.1 双入口设计

#### 入口 A：分析页 Step 4

在现有教学方案展示页中保留原有导出能力，同时新增课件工作流入口。

保留：

- 导出 PPT
- 导出 Word
- 导出 HTML

新增：

- 生成教学课件
- 进入课件编辑器

其中：

- “导出 HTML”保持为快速兼容导出路径
- “生成教学课件”表示创建一个 `CoursewareProject`
- “进入课件编辑器”表示进入项目化 HTML 课件工作流

#### 入口 B：导航一级模块

Navbar 新增一级入口：

- 教学课件

建议该模块作为课件列表与工作台入口，支持：

1. 从已有教案生成课件
2. 导入已有 HTML
3. 从空白模板新建

### 5.2 第一阶段主流程

建议重点打磨以下主流程：

1. 老师完成课文分析并生成教学方案
2. 点击“生成教学课件”
3. 选择课件模式：幻灯片式 / 长页面式
4. 选择课件模板：讲授型 / 活动型 / 学术简报型等
5. 系统生成课件项目草案
6. 自动进入编辑器
7. 老师进行可视化编辑
8. 保存为版本快照
9. 进入课堂展示或导出 HTML

### 5.3 补充流程

#### 补充流程 1：导入已有 HTML

- 教学课件首页 → 导入 HTML → 自动建项目 → 编辑 → 保存 / 展示 / 导出

#### 补充流程 2：空白模板新建

- 教学课件首页 → 选择模板 → 空白起稿 → 编辑 → 保存 / 展示 / 导出

## 6. 信息架构

### 6.1 前端页面结构建议

新增或调整页面：

- `/courseware`：课件列表页
- `/courseware/new`：课件创建入口（可做成面板或弹窗）
- `/courseware/[id]`：课件项目详情 / 概览页
- `/courseware/[id]/edit`：课件编辑页
- `/courseware/[id]/present`：课堂展示页

### 6.2 教学课件首页

功能：

- 最近课件列表
- 从教案生成
- 导入 HTML
- 空白模板新建
- 模板推荐
- 组件库入口（官方 / 我的 / 社区）

### 6.3 编辑页

结构建议：

- 顶部：项目名、模式、保存、版本、展示、导出
- 左侧：页面树 / 教学大纲 / 模块结构 / 素材 / 组件库
- 中间：画布
- 右侧：属性面板
- 辅助区域：版本历史、快照说明、资源清单

### 6.4 展示页

是独立运行态，不显示编辑工具。

支持：

- 幻灯片播放 / 长页面滚动
- 全屏
- 教师备注
- 计时器
- 流程导航
- 本地互动
- 重点聚焦 / 黑屏控制

## 7. 核心对象模型

### 7.1 `TeachingPlan`

现有对象，继续保留，作为教学语义来源。

包含：

- 难度概览
- 教学建议
- 活动设计
- 差异化策略
- 理论依据
- 来源引用
- 学习者适配信息

### 7.2 `CoursewareProject`

新增核心对象。老师真正管理与反复编辑的单位。

建议字段：

- `id`
- `owner_user_id`
- `title`
- `source_type`：`from_plan | imported_html | blank_template`
- `source_plan_id`（可空）
- `mode`：`slides | longform`
- `template_id`
- `status`：`draft | in_editing | ready_to_present | archived`
- `current_version_id`
- `presentation_profile_id`
- `created_at`
- `updated_at`

### 7.3 `CoursewareVersion`

版本必须采用不可变快照。

建议字段：

- `id`
- `project_id`
- `version_number`
- `parent_version_id`
- `save_type`：`autosave | manual_snapshot | published_classroom`
- `editor_schema_json`
- `rendered_html`
- `asset_manifest_json`
- `structure_sync_json`
- `change_summary`
- `created_by`
- `created_at`

说明：

- `editor_schema_json`：编辑器理解的课件结构
- `rendered_html`：当前版本可直接运行的 HTML
- `asset_manifest_json`：资源清单
- `structure_sync_json`：记录与原始教学结构的映射关系

### 7.4 `PresentationProfile`

展示态配置对象。

建议字段：

- 默认展示模式
- 是否允许全屏
- 是否显示教师备注
- 是否启用本地互动
- 是否启用逐步揭示
- 是否启用计时器
- 是否显示课堂导航
- 课堂主题
- 快捷键映射

### 7.5 `ExportArtifact`

导出产物对象。

建议字段：

- `id`
- `project_id`
- `version_id`
- `format`：`pptx | docx | html_single | html_package`
- `file_path` / `object_key`
- `generated_at`
- `generated_by`
- `source`：`from_plan | from_courseware`

### 7.6 `ComponentDefinition`

教学组件定义对象。

建议字段：

- `id`
- `owner_user_id`
- `scope`：`official | personal | community`
- `name`
- `slug`
- `summary`
- `preview_cover`
- `category`
- `teaching_stage`
- `subject_tags`
- `interaction_level`
- `mode_support`
- `schema_json`
- `render_template_html`
- `style_bundle`
- `asset_bundle`
- `version`
- `is_publishable`
- `community_status`

## 8. 三层存储结构

为同时支持结构化教学与强 HTML 编辑，建议底层采用三层结构：

### 8.1 教学结构层

来源：`TeachingPlan`

用途：

- 生成课件草案
- 保留教学语义
- 复用与检索
- 模板派生

### 8.2 课件项目层

来源：`CoursewareProject + CoursewareVersion.editor_schema_json`

用途：

- 可视化编辑
- 页面管理
- 模式切换
- 版本管理
- 组件配置

### 8.3 运行产物层

来源：`rendered_html + assets + exports`

用途：

- 课堂展示
- 单文件导出
- 完整课件包导出
- 分享与归档

## 9. 编辑器定位与体验设计

### 9.1 编辑器定位

平台版编辑器定位为：

> **教学优先的可视化课件编辑器**

不是通用网页搭建器，不以 HTML / CSS / DOM 为用户心智，而以课堂课件的页面、模块、活动和节奏为心智。

### 9.2 继承现有编辑器原型的能力

项目根目录中的 `入口.html` 已具备较强基础，应作为平台化改造内核。

建议直接继承：

- HTML 导入能力
- 可视化选中与属性面板
- 拖拽布局调整
- 页面管理
- 素材池
- 导出能力
- 响应式预览
- 编辑态 / 预览态切换
- 版本快照能力

### 9.3 平台版需要增加的教学化封装

#### A. 课件结构视图

左侧不仅显示页面列表，还应支持：

- 页面视图
- 教学大纲视图
- 模块结构视图

#### B. 教学组件库

用户操作对象应是教学块，而不是技术块。

#### C. 双模式编辑

统一编辑器内核下支持：

- 幻灯片式组织
- 长页面式组织

#### D. 结构化可控区 + 自由编辑区共存

结构化可控区：

- 标题
- 教学目标
- 活动名称 / 步骤
- 理论依据块

自由编辑区：

- 布局
- 装饰
- 多媒体
- 个性化讲解块
- 自定义互动排列

### 9.4 关键交互原则

应强化：

- 点击即选中
- 双击即改字
- 拖拽即移动
- 右侧改样式
- 左侧调结构
- 顶部保存 / 预览 / 展示 / 导出

应隐藏：

- HTML 源码
- class 命名
- CSS 复杂参数
- 原始 DOM 概念

### 9.5 AI 角色边界

第一阶段中，AI 的主要角色是：

- 生成初版课件草案

之后以人工编辑为主，不在编辑器内部引入高频重生成逻辑。重点放在人工高效精修、模板切换、展示控制、版本保存和导出稳定性。

## 10. 教学组件库设计

### 10.1 三层组件库

#### 官方组件库

由平台维护，保证质量、教学适配性和模板一致性。

#### 个人组件库

老师可将改好的组件或课件区块沉淀到个人库中复用。

#### 社区共享组件库

用户可上传组件，其他用户可下载、复用、二次编辑，形成类似 skills 的组件生态。

### 10.2 分类原则

组件分类不按技术组件分，而按真实教学任务与课堂流程组织。

一级分类建议：

1. 课程导入
2. 知识讲授
3. 阅读 / 分析
4. 活动组织
5. 检测反馈
6. 总结反思
7. 作业延伸
8. 教师辅助

### 10.3 第二层标签建议

- 教学任务：词汇教学 / 长难句分析 / 阅读理解 / 小组讨论 / 批判性思维等
- 模式标签：幻灯片适配 / 长页面适配 / 双模式通用
- 互动标签：静态展示 / 点击揭示 / 步骤展开 / 计时互动 / 本地互动
- 时机标签：开场 / 讲授中 / 练习中 / 总结时 / 课后
- 适用对象：大学英语 / 学术英语 / 高中英语 / 小语种 / 文学阅读等

### 10.4 第一阶段官方组件优先级

第一阶段应优先设计高频、实用、立即可上课使用的组件，例如：

#### 课程导入类
- 课程封面页
- 问题导入卡
- 情境导入页
- 学习目标页

#### 知识讲授类
- 词汇讲解卡
- 词汇对比卡
- 长难句拆解卡
- 概念说明卡
- 理论依据卡

#### 阅读 / 分析类
- 文本分段阅读卡
- 结构分析页
- 关键句聚焦卡
- 对比分析页
- 证据链分析卡

#### 活动组织类
- 小组讨论任务卡
- Pair Work 活动卡
- 课堂任务流程卡
- 角色扮演卡
- 案例分析卡

#### 检测反馈类
- 单选题展示块
- 多选题讨论块
- 判断题快检卡
- 点击揭晓答案卡
- 倒计时练习块

#### 总结反思类
- 本课总结页
- Takeaways 卡
- 反思提问卡
- Exit Ticket 页

#### 作业延伸类
- 作业布置页
- 拓展阅读卡
- 继续思考卡

#### 教师辅助类
- 教师备注块
- 板书提示块
- 课堂流程导航
- 重点聚焦 / 黑屏控制块
- 节奏控制条

### 10.5 组件定义合同

每个组件不应是裸 HTML 片段，而应是一份完整定义，至少包含：

- 名称
- 分类
- 标签
- 适配模式
- 适用场景说明
- 可编辑字段
- 默认样式
- 展示行为
- 预览图
- 作者 / 来源
- 版本号

### 10.6 个人组件沉淀方式

建议支持两种个人组件生成方式：

#### 方式 A：从现有组件二次编辑后另存
- 老师修改官方组件后，点击“保存为我的组件”

#### 方式 B：从课件页面中提取区块
- 老师在课件中选定一块内容，点击“提取为组件”

### 10.7 社区共享机制

建议机制：

- 我的组件 → 填写名称 / 简介 / 标签 / 预览图 → 提交社区
- 社区卡片可查看预览、作者、适用课型、模式支持、下载量
- 用户点击“下载到我的组件库”，而不是在线依赖

原则：

- 下载到本地库或项目中，避免课堂使用受远程依赖影响
- 社区优先强调复用与教学场景说明，而不是代码开放能力

## 11. 课堂展示模式设计

### 11.1 展示态与编辑态分离

展示态是独立运行时，不显示编辑器面板与拖拽能力。

- 编辑态：面向备课
- 展示态：面向上课

### 11.2 幻灯片式展示

特点：

- 一页一页切换
- 投屏友好
- 适合讲授节奏控制
- 支持逐页推进、页内揭示、快速翻页

适用：

- 传统课堂投屏讲授
- 导入页 / 活动页 / 总结页明确分离的场景

### 11.3 长页面式展示

特点：

- 连续滚动
- 章节导航
- 模块分段
- 更适合阅读型、讲义型课件

适用：

- 连续阅读讲解
- 结构分析
- 图文混合较多的课程内容

### 11.4 本地互动能力

第一阶段只做本地互动，不做学生端实时联动。

建议支持：

- 点击揭晓答案
- 分步展开
- 限时任务
- 翻卡 / 抽题
- 区域聚焦 / 遮罩控制

### 11.5 教师辅助功能

建议展示态内置：

- 教师备注
- 计时器
- 流程控制条
- 黑屏 / 白屏 / 聚焦
- 课堂导航

### 11.6 控制方式

建议支持常见键盘控制：

- `← / →`：上一页 / 下一页
- `空格`：下一步揭示
- `Esc`：退出全屏
- `B`：黑屏
- `T`：计时器开关
- `N`：教师备注开关
- `H`：隐藏辅助 UI

### 11.7 导出形态与展示关系

第一阶段支持双输出：

#### 单文件便携版

- 一个 HTML 文件拷走即用
- 尽量自包含
- 适合课堂直接打开

#### 完整课件包版

- HTML + assets + manifest
- 更适合复杂多媒体与继续编辑
- 更适合项目长期管理

## 12. 与现有系统的整合方式

### 12.1 保持不动的能力

以下现有主链路保持原有语义：

- 白盒分析
- 双源检索
- 教案生成
- 教案修订
- 教案导出 PPT / Word / HTML

### 12.2 现有 HTML 导出的角色升级

当前 `backend/app/services/analysis/export_service.py` 中的 `export_html()` 负责教学方案数据到单文件 HTML 模板注入。

建议未来拆分语义：

#### A. 教案 HTML 快速导出
- 保留当前导出逻辑作为兼容路径

#### B. 课件项目草案生成渲染器
- 从教学方案结构生成课件项目初稿
- 供编辑器接管后续流程

### 12.3 分析页 Step 4 升级策略

保留现有导出按钮，同时新增：

- 生成教学课件
- 进入课件编辑器

### 12.4 编辑器原型接入方向

项目根目录 `入口.html` 作为平台版课件编辑器内核原型，需升级为支持：

- 项目元数据
- 模式信息
- 页面结构
- 组件定义
- 资源清单
- 版本上下文

## 13. 结构同步边界

由于采用双层模型，必须明确哪些信息可回写到教学结构层，哪些不应强行回写。

### 13.1 可回写内容

- 课件标题
- 教学目标块
- 活动标题
- 活动顺序
- 理论依据块
- 结构化备注区

### 13.2 不强制回写内容

- 复杂视觉布局
- 自定义媒体组合
- 动效
- 装饰性元素
- 高自由度互动组合块
- 临场添加的碎片化讲解区

原则：

> 平台保留“可识别的教学骨架”，但不试图把老师所有深度 HTML 编辑重新解释回教学方案。

---

## 14. 第一阶段的实现边界判断

本模块本质上不是单个功能，而是一个“HTML 课件子系统”，包含：

1. 课件生成器
2. 课件编辑器
3. 项目与版本管理
4. 课堂展示端
5. 组件库与组件复用机制

因此第一阶段的“完整闭环”定义为：

> **聚焦的课件工作流完整闭环，而不是所有潜在能力的一次性实现。**

换言之，第一阶段应做到：

- 业务路径完整
- 教师使用真实可行
- 平台亮点足够明显
- 结构上为未来扩展留下空间

但不应演变为：

- 通用低代码网页平台
- 实时互动教学系统
- 高保真跨格式无损转换引擎

## 15. 推荐命名

### 15.1 对用户展示的模块名

推荐：

- 教学课件

原因：

- 对教师语义最直观
- 不把产品认知锁死在技术名词 HTML 上
- 更适合未来课件列表、模板、组件库与课堂展示等能力扩展

### 15.2 对内能力称谓

推荐内部统一称为：

- HTML 课件工作台
- HTML 课件项目
- 教学组件库

## 16. 最终结论

本次中期升级不应被理解为“新增一个 HTML 导出功能”，而应被理解为：

> **在保留 PPT / Word 传统导出能力的同时，新增一个以 HTML 为核心、可生成、可编辑、可版本化、可课堂展示、可组件化复用的教学课件工作台子系统。**

它的最终产品形态是：

- 对上承接教学方案生成
- 对内沉淀课件项目与组件资产
- 对下直接服务教师课堂展示
- 对外成为平台中期阶段最重要的差异化亮点之一

## 17. 当前确认状态

以下关键方向均已确认：

- HTML 与 PPT 并列，不删除 PPT / Word
- HTML 是平台宣传重点之一
- 双模式共存：幻灯片式 + 长页面式
- 双层模型：教学结构层 + 课件文档层
- 平台内重编辑优先
- 双入口：分析页 + 独立工作台
- 三种起点：从教案生成 / 导入 HTML / 空白新建
- 生成后以人工编辑为主，AI 主要负责初稿生成
- 导出支持单文件版与完整课件包版
- 互动第一阶段仅做本地互动
- 第一阶段不做学生端实时互动与 HTML 高保真反导出 PPT / Word
- 组件库采用官方 / 个人 / 社区三层结构
- 社区组件支持上传、下载、复用，形成类似 skills 的共创生态
